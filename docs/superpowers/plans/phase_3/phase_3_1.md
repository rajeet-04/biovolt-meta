# Phase 3.1: PlatformIO Firmware Foundation and Testable Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bootstrap the ESP32 firmware project with reproducible PlatformIO builds, host-testable pure C++ core types, and a minimal safe boot skeleton before hardware drivers are introduced.

**Architecture:** Keep pure protocol/safety/timing logic in `lib/BioVoltCore` so it can run under PlatformIO `native` tests. ESP32-only code stays under `src/`. `main.cpp` does only serial initialization, safe GPIO initialization, configuration loading hooks, and task startup hooks added by later modules.

**Tech Stack:** PlatformIO, ESP32 Arduino Framework, C++17, Unity tests.

**Spec:** `docs/architecture/software-architecture.md`

## Global Constraints

- Firmware target is `esp32dev` / ESP32 DevKit V1 class hardware.
- C++ standard is GNU++17.
- No sensor, Wi-Fi, or actuator business logic is placed directly in Arduino `loop()`.
- `loop()` remains idle except a small `vTaskDelay` after later FreeRTOS tasks start.
- Pure core files must not include `Arduino.h` so native tests remain fast.
- Firmware starts from safe actuator defaults.
